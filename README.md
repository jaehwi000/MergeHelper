# 주문 엑셀 합치기

여러 마켓(스마트스토어, 쿠팡, 자사몰 등)에서 내려받은 주문 엑셀을 브라우저에 올리면, 하나로 합쳐 다음 세 가지 파일을 만들어 주는 무료 도구입니다.

- **택배사 업로드용**: 같은 사람·연락처·주소의 주문을 합포장으로 묶어 한 줄이 한 박스
- **피킹 리스트**: 상품별 수량 합계(인쇄 가능)
- **통합 주문표**: 모든 주문과 원래 마켓·주문번호

택배사에서 송장번호를 받은 뒤에는 **송장번호 되돌려 넣기**(2단계)로, 올렸던 마켓별 원본 주문 파일에 택배사·송장번호를 채운 발송처리 파일을 만들 수 있습니다.

주문 파일은 **브라우저 안에서만** 처리되고 서버로 전송되지 않습니다. 페이지의 보안 정책(CSP)이 외부 전송을 막습니다.

## 쓰는 법

1. `app/index.html`을 브라우저로 엽니다. 더블클릭해서 열어도 되고, 인터넷 연결 없이도 동작합니다.
2. 마켓에서 내려받은 주문 파일(xlsx, xls, csv)을 끌어다 놓습니다.
3. 인식되지 않은 파일은 "열 직접 연결하기"에서 주문번호·수취인 등이 어느 열인지 한 번만 알려 줍니다(다음부터 자동).
4. 합포장 묶음을 확인하고, 필요하면 상품명 줄임말을 정합니다.
5. 필요한 파일을 내려받습니다.
6. (2단계) 택배사에 접수해 송장번호가 나오면, 창을 닫지 말고 "송장번호 넣기"에서 택배사 결과 파일을 올립니다.
   - 원주문번호 열이 남아 있으면 그것으로, 없으면 받는분 이름 + 연락처(가려진 번호는 뒤 4자리)로 박스를 찾습니다.
   - 찾지 못한 박스는 표에 직접 입력합니다. 직접 입력한 번호는 결과 파일보다 우선합니다.
   - 마켓별로 "발송처리_마켓_날짜.xlsx"를 내려받아 각 마켓의 송장 일괄 등록 화면에 올립니다.

샘플 파일은 `samples/` 폴더에 있고, 화면의 "샘플 파일로 체험하기"로도 바로 볼 수 있습니다.

## 지원 범위

| 항목 | 상태 |
|---|---|
| 스마트스토어·쿠팡 자동 인식 | 열 이름은 **추정값**입니다. 실제 다운로드 파일로 확인이 필요합니다(`app/js/core/markets.js`) |
| 그 밖의 쇼핑몰 | 열 이름으로 추측하거나 직접 연결 |
| CSV 인코딩 | UTF-8, EUC-KR(CP949) 자동 판별 |
| 암호 걸린 엑셀 | 열 수 없음. 암호를 지우고 다시 저장하도록 안내 |
| 택배사 전용 양식 | 아직 없음(기본 양식만 제공) |
| 송장번호 되돌려 넣기 | 원본 주문 파일에 택배사·송장번호를 채워 줌. 스마트스토어 '택배사'·'송장번호', 쿠팡 '택배사'·'운송장번호' 열(추정)에 넣고, 없으면 맨 뒤에 열을 추가. **각 마켓 일괄 등록 양식과 택배사 표기로 검증 필요** |
| 한 박스가 여러 송장으로 나뉜 경우 | 첫 번째 송장만 연결하고 나머지는 알려 줌 |

## 배포 (GitHub Pages)

`main`에 `app/`이나 `tests/`가 바뀌어 올라오면 `.github/workflows/pages.yml`이 단위 테스트를 돌린 뒤 `app/` 폴더를 GitHub Pages로 배포합니다.

처음 한 번만 설정이 필요합니다.

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿉니다.
2. **Actions** 탭에서 "Deploy to GitHub Pages"를 열고 **Run workflow**로 한 번 실행합니다(이후에는 push할 때마다 자동).
3. 주소는 `https://jaehwi000.github.io/demo/` 입니다.

비공개 저장소의 Pages는 GitHub 유료 요금제(Pro 이상)에서만 쓸 수 있습니다. 무료 요금제라면 저장소를 공개로 바꿔야 합니다.

## 개발

빌드 과정 없는 정적 웹페이지입니다.

```
app/
  index.html, styles.css
  js/core/      데이터 처리(파일 해석, 합치기, 합포장, 내보내기, 송장 연결) — 화면과 무관, Node에서 테스트
  js/app.js     화면 동작
  js/samples.js 샘플 주문 데이터
  vendor/       SheetJS
samples/        샘플 주문 파일과 택배사 결과 파일(npm run samples로 다시 생성)
tests/          core.test.mjs(단위), e2e.mjs(브라우저)
```

```bash
npm test          # 단위 테스트 (Node 18+)
npm run e2e       # 브라우저 테스트 (Playwright + Chromium, python3 필요)
npm run samples   # samples/ 다시 만들기
npm run serve     # http://localhost:8000 에서 열기
```

마켓 인식 규칙을 고치거나 추가하려면 `app/js/core/markets.js`를, 열 이름 추측 규칙은 `app/js/core/fields.js`를 수정합니다.

## 배포 전 할 일

- **SheetJS 교체**: 지금은 npm에 올라온 마지막 버전인 0.18.5를 넣어 두었습니다. 이 버전에는 알려진 취약점(CVE-2023-30533, CVE-2024-22363)이 있습니다. 공식 배포처(cdn.sheetjs.com)에서 0.20.3 이상의 `xlsx.full.min.js`를 받아 `app/vendor/`의 파일을 바꿔 주세요. 사용법이 같아서 코드 수정은 필요 없습니다.
- 스마트스토어·쿠팡 실제 주문 파일(개인정보를 가짜로 바꾼 것)로 열 이름 확인
- 실제 택배사 결과 파일과 마켓별 송장 일괄 등록 양식으로 2단계 확인(특히 마켓이 받는 택배사 이름 표기)
