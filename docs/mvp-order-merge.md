# MVP 설계: 주문 엑셀 합치기

- 작성일: 2026-10-15
- 근거: [research/01-pain-points.md](../research/01-pain-points.md)의 A1(주문 파일 취합), A2(다채널 관리)
- 프로토타입: [docs/prototype/order-merge.html](prototype/order-merge.html) (샘플 데이터로 눌러볼 수 있는 화면)

## 1. 한 줄 정의

여러 마켓에서 내려받은 주문 엑셀을 **브라우저에 끌어다 놓기만 하면**, 하나의 주문표·택배 업로드 파일·피킹 리스트로 바꿔 주는 무료 웹 도구.

## 2. 대상과 문제

| 항목 | 내용 |
|---|---|
| 대상 | 2~4개 마켓에서 판매하는 **월 주문 100~1,000건** 규모의 1인·소규모 셀러 |
| 지금 하는 일 | 마켓별 주문 엑셀 다운로드 → 엑셀에서 열 순서 맞추기 → 복사·붙여넣기로 합치기 → 같은 주소 주문 눈으로 찾아 합포장 → 택배사 양식으로 다시 옮기기 |
| 불편 | 매일 반복, 붙여넣기 실수(열 밀림·누락), 합포장 누락으로 택배비 이중 지출 |
| 기존 대안 | 사방넷·셀메이트 등 통합관리 솔루션(월 3만 원 안팎, 기능 과다·학습 부담) |

## 3. MVP 범위

### 포함
1. 여러 파일 동시 업로드(xlsx, xls, csv)
2. **마켓 자동 인식**(헤더 이름으로 판별)과 표준 열로 변환
3. 인식 실패 시 **열 직접 연결(매핑)** 화면, 연결 결과는 브라우저에 기억
4. **합포장 후보 자동 묶기**(수취인 + 연락처 + 주소가 같으면 한 묶음), 묶음 해제 가능
5. **상품명 줄임말**(긴 마켓 상품명 → 내가 정한 짧은 이름), 브라우저에 기억
6. 내보내기 3종: 통합 주문표, 택배사 업로드용, 피킹 리스트(상품·옵션별 수량 합계)

### 제외 (다음 단계)
- 송장번호를 마켓별 "일괄 발송" 양식으로 되돌려 넣기 → **2단계 1순위**
- 마켓 API 연동(자동 주문 수집), 재고 연동
- 로그인·서버 저장·결제

### 원칙
- **주문 데이터는 서버로 보내지 않는다.** 모든 처리는 브라우저 안에서 끝난다. 주문 파일에는 이름·전화번호·주소가 들어 있으므로 이것이 핵심 신뢰 포인트다.
- 설정(열 매핑, 상품명 줄임말, 택배사 선택)만 브라우저 저장소에 남긴다.

## 4. 사용자 흐름

```
[1 파일 올리기] → [2 파일 확인] → [3 주문 정리] → [4 내려받기]
                      │
                      └─ 인식 실패 파일 → [2-1 열 연결] ─┘
```

목표 소요 시간: 처음 사용 3분 이내, 두 번째부터 **30초 이내**(설정이 기억되므로 올리고 → 확인 → 다운로드).

## 5. 화면별 설계

### S1. 파일 올리기

```
┌──────────────────────────────────────────────┐
│ 주문 엑셀 합치기                    도움말   │
├──────────────────────────────────────────────┤
│  ① 파일 올리기  ② 확인  ③ 정리  ④ 내려받기   │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │   여기에 주문 엑셀 파일을 끌어다 놓으세요  │  │
│  │      또는 [파일 선택]  (여러 개 가능)    │  │
│  │   xlsx · xls · csv                     │  │
│  └────────────────────────────────────────┘  │
│                                              │
│  🔒 파일은 이 브라우저 안에서만 처리되며     │
│     어디에도 업로드되지 않습니다.            │
│                                              │
│  지원 마켓: 스마트스토어 · 쿠팡 · 11번가 ·    │
│            G마켓/옥션 · 기타(직접 연결)       │
│                                              │
│  [샘플 파일로 체험해 보기]                    │
└──────────────────────────────────────────────┘
```

- 파일을 놓으면 바로 S2로 이동한다.
- "샘플로 체험"은 실제 파일 없이도 가치를 보여 주는 장치다(첫 방문자용).
- 오류: 지원하지 않는 형식 → "엑셀(xlsx, xls) 또는 csv 파일만 올릴 수 있어요."
- 오류: **암호가 걸린 파일** → 비밀번호 입력창을 띄우거나, 해제 방법을 안내한다(아래 8절 위험 참고).

### S2. 파일 확인

```
┌──────────────────────────────────────────────┐
│  ① ✓  ② 확인  ③  ④                           │
│                                              │
│  올린 파일 3개 · 주문 47건                   │
│  ┌──────────────────────────────────────┐    │
│  │ ✓ 스마트스토어  주문_1015.xlsx   23건 │ ✕  │
│  │ ✓ 쿠팡         DeliveryList.xlsx 18건 │ ✕  │
│  │ ! 인식 못 함    orders.csv        6건 │ ✕  │
│  │   └ [열 직접 연결하기]                │    │
│  └──────────────────────────────────────┘    │
│  [+ 파일 더 올리기]                           │
│                                              │
│  ⚠ 중복 의심 2건: 같은 주문번호가 두 파일에   │
│    있어요. [보기]                            │
│                                              │
│                       [다음: 주문 정리 →]     │
└──────────────────────────────────────────────┘
```

- 파일별로 인식된 마켓, 건수, 상태(정상 / 확인 필요 / 인식 실패)를 보여 준다.
- 같은 파일을 두 번 올렸거나 같은 주문번호가 겹치면 **중복 경고**를 띄운다(합쳤을 때 이중 발송 방지).
- 인식 실패 파일이 있어도 나머지는 진행 가능하다(그 파일은 제외하고 진행).

```
│  연락처        *   [ 받는분 휴대폰   ▾ ]      │
│  주소          *   [ 배송지          ▾ ]      │
│  상품명        *   [ 품목            ▾ ]      │
│  수량          *   [ 수량            ▾ ]      │
│  옵션              [ 선택 안 함      ▾ ]      │
│  우편번호          [ 우편번호        ▾ ]      │
│  배송메모          [ 요청사항        ▾ ]      │
│                                              │

```

- 드롭다운 기본값은 열 이름 유사도로 미리 채운다("받는분" → 수취인).
- 저장한 매핑은 **헤더 목록이 같으면** 다음부터 자동 적용한다.

### S3. 주문 정리 (핵심 화면)

```
┌────────────────────────────────────────────────────────────┐
│  ① ✓  ② ✓  ③ 정리  ④                                       │
│                                                            │
│  주문 47건 → 발송 41박스 (합포장 6묶음)                    │
│  [전체] [스마트스토어 23] [쿠팡 18] [자사몰 6]  🔍 검색     │
│                                                            │
│  ┌──┬─────────┬──────┬────────┬───────────────┬──┬────┐   │
│  │☑ │마켓      │수취인 │연락처   │상품(줄임말)    │수량│묶음 │   │
│  ├──┼─────────┼──────┼────────┼───────────────┼──┼────┤   │
│  │☑ │스마트    │김민지 │...5678 │유기농 현미 1kg │ 2│ ┐ 1 │   │
│  │☑ │쿠팡      │김민지 │...5678 │귀리 500g       │ 1│ ┘   │   │
│  │☑ │스마트    │이서준 │...1234 │현미 1kg        │ 1│     │   │
│  │  ...                                                    │
│  └────────────────────────────────────────────────────────┘   │
│                                                            │
│  상품명 줄임말 3개 미설정  [설정하기]                       │
│                         [← 이전]   [다음: 내려받기 →]       │
└────────────────────────────────────────────────────────────┘
```

- **합포장 묶음**은 같은 색 띠와 묶음 번호로 표시한다. 묶음을 누르면 "묶음 풀기"가 가능하다.
- 마켓이 달라도 합포장 대상이 될 수 있다(위 예시처럼 스마트스토어 + 쿠팡). 단, 마켓별 발송처리는 따로 해야 하므로 내보낼 때 원래 주문번호를 모두 남긴다.
- 체크를 해제한 주문은 내보내기에서 빠진다(예: 취소 요청 들어온 건).
- **상품명 줄임말**: 원래 상품명+옵션 조합별로 짧은 이름을 정한다. 송장·피킹 리스트에는 줄임말이 찍힌다.
- 휴대폰 화면에서는 표 대신 카드 목록(수취인·상품·수량·묶음)으로 바꿔 보여 준다.

## 6. 데이터 설계

### 6-1. 표준 주문 항목

| 표준 항목 | 필수 | 설명 |
|---|---|---|
| market | ✓ | 마켓 이름(자동 인식 또는 사용자가 지정) |
| orderNo | ✓ | 마켓 주문번호(마켓마다 "상품주문번호"처럼 더 작은 단위가 있으면 그것을 사용) |
| receiver | ✓ | 수취인 이름 |
| phone | ✓ | 수취인 연락처 |
| address | ✓ | 전체 주소 |
| zip |  | 우편번호 |
| product | ✓ | 원래 상품명 |
| option |  | 옵션 |
| qty | ✓ | 수량 |
| memo |  | 배송 메모 |
| amount |  | 결제 금액(통합 주문표에만 사용) |

### 6-2. 마켓 자동 인식 규칙

- 각 마켓의 **특징적인 헤더 이름 조합**으로 판별한다. 예: "상품주문번호" + "수취인명"이 있으면 스마트스토어, "묶음배송번호" + "노출상품명"이 있으면 쿠팡.
- **주의: 실제 헤더 이름은 아직 검증하지 않았다.** 개발 전에 마켓별 실제 다운로드 파일(개인정보를 지운 것)로 헤더 목록을 확정해야 한다. 마켓이 양식을 바꿀 수 있으므로 인식 규칙은 코드가 아니라 **설정 파일(JSON)**로 분리한다.

### 6-3. 합포장 규칙

- 키: `정규화(수취인) + 정규화(연락처 숫자만) + 정규화(주소)`
  - 연락처: 숫자만 남김(010-1234-5678 → 01012345678)
  - 주소: 공백 정리, "특별시/광역시" 축약 차이 통일, 괄호 안 참고항목 제거
- 키가 같으면 한 묶음. 주소만 같고 이름이 다르면 **자동으로 묶지 않고** "합포장 가능?" 표시만 한다(가족 주문 등).
- 배송 메모가 서로 다르면 묶음에 ⚠ 표시하고 메모를 합쳐 보여 준다.

## 7. 기술 방향

- **정적 웹페이지 1개**(서버 없음). GitHub Pages로 무료 배포 가능.
- 엑셀 읽기·쓰기: SheetJS(xlsx) 라이브러리.
- 저장: 설정만 localStorage. 주문 데이터는 새로고침하면 사라진다(의도된 동작이며 화면에 명시).
- 인식 규칙·택배사 양식은 JSON 설정으로 관리해 마켓 양식 변경 시 코드 수정 없이 대응한다.

## 8. 위험과 확인할 것

| 위험 | 영향 | 대응 |
|---|---|---|
| 마켓 주문 파일에 **비밀번호(암호화)**가 걸려 나오는 경우 | 브라우저에서 바로 읽지 못할 수 있음 | 실제 파일로 확인 필요. 암호화가 기본이면 ① 브라우저 복호화 라이브러리 검토 ② "엑셀에서 암호 해제 후 다시 저장" 안내 중 결정 |
| 실제 헤더 이름이 추정과 다름 | 자동 인식 실패 | 실제 샘플 파일 확보 후 규칙 확정, 실패해도 S2-1 매핑으로 진행 가능 |
| 마켓 양식 변경 | 인식 실패 | 규칙을 JSON으로 분리, 매핑 화면이 안전망 |
| 합포장 오탐(다른 사람인데 묶임) | 오배송 | 이름·연락처·주소가 모두 같을 때만 자동 묶기, 묶음 해제 쉽게 |
| 개인정보 우려로 사용 꺼림 | 사용자 확보 어려움 | "서버 전송 없음"을 첫 화면에 명시, 오프라인에서도 동작함을 보여 주기 |

## 9. 개발 전에 확보할 것

1. 스마트스토어·쿠팡 주문 다운로드 파일 샘플 각 1개(개인정보는 가짜로 바꾼 것)
2. 가장 많이 쓰는 택배사 1~2곳의 대량 접수(업로드) 양식
3. 실제 셀러 2~3명에게 프로토타입을 보여 주고 확인할 질문
   - 지금 하루에 이 작업에 몇 분 쓰는지
   - 합포장을 어떻게 판단하는지(이름까지 같아야 하는지)
   - 송장번호를 마켓에 다시 넣는 작업(2단계)이 더 급한지

## 10. 성공 기준 (MVP)

- 샘플 파일 3종(마켓 2개 + 기타 1개)을 올려 **30초 안에** 택배 업로드 파일을 받을 수 있다.
- 같은 사람의 다른 마켓 주문이 합포장으로 묶여 보인다.
- 두 번째 사용부터 매핑·상품명 줄임말을 다시 입력하지 않는다.
- 브라우저 개발자 도구의 네트워크 탭에 주문 데이터 전송이 없다.
